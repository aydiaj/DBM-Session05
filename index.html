using System.ComponentModel.DataAnnotations.Schema;

namespace EF10_InventoryModels;

public class Item
{
    public int Id { get; set; }

    [Required]
    [StringLength(100)]
    public string Name { get; set; } = "";

    [Column(TypeName = "decimal(10,2)")]

    What does each important line mean?
    Line / symbol Meaning
    using System.ComponentModel.DataAnnotations; Makes Required and StringLength available. A using directive imports names; it does not install a package.
    [Required] The Name property is required in EF’s model.
    [StringLength(100)] Sets the model’s maximum Name length to 100.
    using System.ComponentModel.DataAnnotations.Schema; Makes the Column mapping attribute available.
    [Column(TypeName = "decimal(10,2)")] Matches UnitPrice to the SQL type: 10 total digits, 2 decimal places.
    public int Id { get; set; } A readable/writable integer property. Id is a primary-key name recognised by convention.
    public string Name { get; set; } = ""; Starts Name as an empty, non-null string. This does not make an empty name valid business data.
    decimal / bool / DateTime Money-style decimal values, true/false values and a date/time value. System types are available through the project’s implicit usings.
    Mapping describes the existing table

    EF matches property and column names by convention. The Items DbSet name supplies the default table name; SQL Server’s default schema here is dbo. Different names need explicit mapping.

    These attributes do not alter this database or run automatic C# input validation. The prepared SQL already defines the column rules.

    What is the provider?

    SQL Server provider (Microsoft.EntityFrameworkCore.SqlServer): EF Core’s component that translates LINQ queries for SQL Server. UseSqlServer(connectionString) selects and configures it.

    Component Job
    DbContextOptionsBuilder Build the context configuration.
    UseSqlServer(...) Select/configure the SQL Server provider.
    Microsoft.Data.SqlClient The underlying ADO.NET driver: connections, commands and results.
    SQL Server The database engine that executes SQL.
    Read each configuration line
    Line Meaning
    var optionsBuilder = new ... Create the builder object. var lets C# infer its type.
    optionsBuilder.UseSqlServer(connectionString) Choose the provider and supply the destination/authentication settings.
    optionsBuilder.Options Read the configuration built so far.
    using var db = new InventoryDbContext(...) Create the context. using disposes it when the enclosing scope ends.
    Console.WriteLine(...) Print a message; this does not test a database connection.
    Configure is not connect

    Creating the context does not open the connection. Building a query does not open it either.

    At ToListAsync(), EF opens the connection, reads the results and normally closes it after the operation. The context can still be alive.

    Printing the loaded list sends no new query. Our using declaration disposes the context when its scope ends.

    STEP 04 / 08 · 20 MINUTES

    Filter and search

    Start with LINQ

    LINQ means Language Integrated Query. It lets us query data using C#. EF Core translates supported LINQ expressions into SQL.

    We use method syntax: start with db.Items, then connect operations using dots.

    The operators we will practise

    Operator Purpose Stage
    Where Keep rows matching a condition. Build the query
    OrderBy Sort by a value. Build the query
    ThenBy Add a second sorting rule. Build the query
    Select Choose the values to return. Build the query
    ToListAsync Retrieve the results as a list. Execute
    CountAsync Return the number of matching rows. Execute
    AnyAsync Return whether a match exists. Execute
    FirstOrDefaultAsync Return one item, or null if none matches. Execute

    This is our roadmap. We begin with filtering, then practise sorting, selecting values and choosing a result type.

    Read one query before writing your own

    Source → condition → execution 
    var items = await db.Items
    .Where(item => item.Stock > 0)
    .ToListAsync();
    • db.Items is our entry point for querying mapped Item entities.
    • Where(...) adds the condition: stock must be greater than zero.
    • ToListAsync() executes the query and retrieves a List<Item>.
    • await waits for that operation to finish. The loaded list is assigned to items.

    What does the arrow mean?

    item => item.Stock > 0 is a lambda expression. Here it describes a condition for an item.

    • item: a parameter representing an Item.
    • =>: separates the parameter from its expression.
    • item.Stock > 0: the condition to test.

    Read it as: “Keep items whose stock is greater than zero.” This filtering condition is called a predicate.

    The parameter name is our choice. i => i.Stock > 0 means the same thing.

    Remember: Where builds the query. In this example, SQL runs when ToListAsync() executes.

    Ask which records should remain

    Where keeps rows that satisfy a condition. Build the condition before ToListAsync().

    Read the predicate 
    item => item.IsActive && item.Stock > 0

    && means both conditions must be true. || means either condition can be true.

    Optional comparison · First or Single?

    FirstOrDefaultAsync returns the first match or null. Use explicit ordering if “first” must be predictable across several matches.

    SingleOrDefaultAsync returns one match or null, and throws if several rows match. It expresses an expectation of uniqueness; it does not create a database constraint.
